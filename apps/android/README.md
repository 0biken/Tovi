# TOVI for Android

Kotlin + Jetpack Compose app over the Rust core. The core is built into
`libtovi_ffi.so` from [`core/tovi-ffi`](../../core/tovi-ffi), and its Kotlin
bindings (package `app.tovi.core`) are generated by UniFFI as part of the
Gradle build (`cargoNdkBuild` → `uniffiBindgen` tasks in `app/build.gradle.kts`).

## Requirements

- JDK 17
- Android SDK with platform 36, build-tools 36.1 and NDK `29.0.14206865`
  (`sdk.dir` in `local.properties`, which Android Studio writes for you)
- Rust with the Android targets, and cargo-ndk:

```sh
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk
```

## Build and run

```sh
./gradlew assembleDebug        # APK in app/build/outputs/apk/debug/
./gradlew testDebugUnitTest    # JVM unit tests
./gradlew installDebug         # onto a connected phone or emulator
```

The APK carries the library for `arm64-v8a` (phones) and `x86_64`
(emulators). The Rust library is always built in release mode; a debug build
of the core is large and slow.

## Layout

- `ToviApp`: owns the process-wide `NodeRepository`.
- `data/NodeRepository`: the one `ToviNode`; turns its events into flows.
- `data/LiveState`: pure reducer from `NodeEvent`s to active transfers and
  pending requests (unit tested).
- `data/OutgoingFiles`: copies picked `content://` documents into the cache,
  since the core reads files by path.
- `ui/`: Devices, Transfers, Settings and Pair screens, plus the dialog that
  answers pairing and incoming-file requests.

## Testing against the desktop app

Use a physical phone on the same Wi-Fi as the computer. An emulator sits
behind its own NAT, so the desktop can't reach it. In the desktop app go to
Pair, click Copy code, send the code to the phone, and paste it into
Pair device.
